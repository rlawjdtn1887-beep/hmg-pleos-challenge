# 2026-10-30 개발 로그 — Pleos 샘플 앱 clone & 테스트

## 개발 환경
- Android Studio, Pleos Connect Emulator v2.1.0 (Android 14, API 34, x86_64)
- Vehicle SDK 2.3.2 / Vehicle Service 2.3.22
- 샘플 요구 환경: JDK 17, Gradle 8.10.2, AGP 8.8.2, Kotlin 2.0.0, compileSdk/targetSdk 35
- 우리 앱은 공모전 조건에 맞춰 minSdk 28 이상

## 환경 설정 메모
- 시스템 이미지: SDK Update Sites에 Pleos 주소 등록 후 SDK Platforms의 API 34에서 설치
- 기기 프로필이 안 보이면 `system-images\android-34\pleos_car_emulator\x86_64\devices.xml` 을 `C:\Users\Owner\.android` 에 복사
- AVD 설정: Cold boot, RAM 4GB, Graphics Hardware
- adb: 사용자 Path에 `%LOCALAPPDATA%\Android\Sdk\platform-tools` 등록, Android Studio 재시작 필요
- Virtual Console: `adb forward tcp:8088 tcp:8088` → http://127.0.0.1:8088/ (에뮬레이터 재시작마다 forward 다시)
- 콘솔과 에뮬레이터 상태가 어긋나면("P switch failed"): BRAKE 누른 채 기어 변경 → 콘솔 새로고침 → 필요 시 Cold Boot

## 샘플 앱 수정 사항

| 파일 | 변경 | 이유 |

## 배운 점
- Vehicle SDK는 capability 확인 → get → register/unregister → set 순서로 사용, 결과는 비동기 콜백
- 같은 리스너 중복 등록 불가 → 구독은 한 번만 하고 반드시 해제(화면이 아니라 ViewModel/별도 클래스에서 관리)
- `distractionOptimized` 미선언 앱은 주행 중 사용 불가
- 샘플에는 기어·차속이 없음 → AAOS API(`PERF_VEHICLE_SPEED`, `GEAR_SELECTION`)로 직접 연결 필요
- SOC가 정수(%)라면 감속 한 번의 회생량은 SOC로 측정 불가 → 물리 모델 추정 검토
